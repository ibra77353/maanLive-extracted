# Prince Live — نظام بث مباشر محلي

نظام بث مباشر **محلي بالكامل** لجهاز واحد: يلتقط من كاميرا/بطاقة التقاط (أو من الشاشة)، ويحوّله بـ FFmpeg إلى مقاطع HLS، ويقدّمها للمشاهدين على الشبكة المحلية، مع لوحة تحكم عربية لإدارة المصادر والقنوات والجدولة والإعلانات.

- **اسم الحزمة:** `amaan-live-local` — والأسماء التجارية/الوصفية المستخدمة: **Prince Live**، وبثي المحلي.
- **اسم التطبيق الظاهر في الواجهة** يأتي من `settings.siteName` (القيمة المرفقة: **بثي المحلي** / `My Live`) ويمكن تغييره من قسم الإعدادات.
- هذا الملف يوثّق **بنية المشروع الفعلية** كما هي في الكود والإعدادات المرفقة، لا كما يُفترض أن تكون.

## 1. نبذة عن المشروع

### ما هو

تطبيق يعمل على جهاز واحد (كمبيوتر البث) بلا إنترنت وبلا ترخيص وبلا قاعدة بيانات، ويقوم بأربعة أمور:

1. **الالتقاط:** يقرأ أجهزة الفيديو والصوت المتصلة فعليًا (كاميرا، بطاقة التقاط، أو التقاط الشاشة) عبر FFmpeg/DirectShow.
2. **التحويل:** يرمّز المصدر إلى HLS (مقاطع `.ts` + قائمة `.m3u8`) بإعدادات الجودة والترميز المختارة.
3. **التقديم:** يخدم ملفات HLS للمشاهدين: مقاطع `.ts` من Nginx مباشرةً من القرص (أسرع وأخف)، وكل ما تبقّى (الواجهات + الـ API + قوائم التشغيل) من Node.
4. **الإدارة:** لوحة تحكم عربية (مصادر، قنوات، جدولة، إعلانات، إعدادات، مراقبة وسجلات) + صفحة مشاهدين مستقلة.

### مكونات النظام

| المكوّن | الوصف | المسار الفعلي |
|---|---|---|
| خادم Node | يقدّم الواجهات والـ API ويدير FFmpeg وNginx | `server.js` + `src/*.js` |
| لوحة الإدارة | صفحة واحدة بستة أقسام (مراقبة/قنوات/مصادر/جدولة/إعلانات/إعدادات) | `public/admin/` → `/admin` |
| صفحة المشاهدين | قائمة القنوات + المشغّل + الشريط المتحرك + الإعلانات | `public/viewer/` → `/` |
| FFmpeg | الالتقاط والترميز وإنتاج HLS | `ffmpeg.exe` (مرفق) |
| Nginx | تقديم مقاطع `.ts` الثقيلة من القرص + تمرير الباقي إلى Node | `nginx/nginx.exe` (مرفق) |
| hls.js | مشغّل HLS في المتصفح (محلي، بلا CDN) | `public/vendor/hls.min.js` |
| الإعدادات | ملف JSON واحد لكل شيء (إعدادات + مصادر + قنوات + إعلانات) | `config/config.json` |

### آلية البث (FFmpeg + HLS + Nginx)

```
جهاز الالتقاط ──► FFmpeg (ترميز/نسخ + تقسيم)
                      │
                      ▼
             srv/hls/<معرّف القناة>/index.m3u8 + seg_*.ts
                      │
        ┌─────────────┴──────────────┐
        ▼                            ▼
Nginx  (مقاطع .ts من القرص)     Node (قوائم m3u8 + الواجهات + API)
    منفذ 801 (أو 80)              منفذ 3001
        └─────────────┬──────────────┘
                      ▼
        المتصفح: صفحة المشاهدين + hls.js  ──►  /hls/<id>/index.m3u8
```

**نقاط أساسية:**

- FFmpeg يكتب المقاطع في مجلد القناة داخل `srv/hls/`، ويحذف الأقدم تلقائيًا (`hls_list_size` و`hls_delete_threshold`).
- المشاهد يطلب قائمة التشغيل ثم المقاطع مباشرة؛ لا وسيط ولا إعادة تحزيم.
- **عدّ المشاهدين** يعتمد على **قراءات HLS الحقيقية**: طلبات قوائم/مقاطع `.ts` التي يخدمها Node، **وكل مقطع `.ts` يخدمه Nginx يُسجَّل في سجل وصوله** (`nginx/logs/access.log`) ويُقرأ من البرنامج. لا تُستخدم نبضات المتصفح، ولذلك تبقى الأرقام صحيحة عند إخفاء تبويب المتصفح أو عند المشاهدة بمشغّل خارجي (VLC مثلاً) لا يرسل أي نبضة.
- يُحتسب المشاهد «حاضرًا» خلال نافذة `viewerWindowSeconds` من آخر قراءة له، ويُبنى على ذلك **إيقاف القناة عند الخمول**.

### بنية المجلدات

```

├─ تشغيل السيرفر.bat            تشغيل بنقرة (يتحقق من المتطلبات ويكتب nginx.conf)

├─ public/

├─ nginx/
│  ├─ nginx.exe                 Nginx مرفق (1.27.4)

│  └─ html/                     صفحة Nginx الافتراضية
├─ srv/
│  ├─ hls/<معرّف القناة>/        ملفات البث (تُنشأ وتُدار تلقائيًا)
```

### وحدات الكود (`src/`)

| الملف | الوظيفة |
|---|---|
| `server.js` | نقطة الدخول: خدمة الملفات الساكنة، تشغيل Nginx، بدء حلقات الخمول/الجدولة/المراقبة، قراءة سجل وصول Nginx، وتسجيل خطوات الإيقاف. |
| `store.js` | التخزين المحلي: `config/config.json`، إنشاء المجلدات، دمج المفاتيح الجديدة، كتابة ذرّية، تجزئة كلمة المرور (scrypt). |
| `http.js` | طبقة HTTP قياسية: موجّه، JSON، خدمة ملفات ساكنة، وقارئ multipart للرفع. |
| `routes.js` | كل مسارات الـ API (عامة + محمية) والتحقق من صحة المدخلات. |
| `auth.js` | مصادقة حساب مسؤول واحد: دخول/خروج، كوكي جلسة موقّع بـ HMAC-SHA256، وحارس للمسارات. |
| `ffmpeg.js` | نواة البث: تشغيل/إيقاف/إعادة، بناء وسائط الإدخال والإخراج، السجلات، الإحصاءات، عدّ المشاهدين من قراءات HLS، وإعادة التشغيل عند التعطل. |
| `devices.js` | اكتشاف أجهزة الفيديو/الصوت وقدراتها الفعلية من مخرجات FFmpeg (DirectShow/الشاشة). |
| `nginx.js` | توليد `nginx.conf` من الإعدادات وتشغيل/إيقاف/فحص Nginx والتحقق من المنافذ. |
| `idle.js` | حلقة إيقاف القنوات عند خمول المشاهدين. |
| `monitor.js` | حلقة كشف تعطّل/تجمّد FFmpeg (قائمة HLS لا تُحدَّث) وإعادة التشغيل. |
| `scheduler.js` | نوافذ تشغيل القنوات (أيام + من/إلى، وتدعم عبور منتصف الليل). |
| `stats.js` | إحصاءات اللوحة: المعالج، باندويث الخروج، والمشاهدون. |
| `lock.js` | قفل النسخة الواحدة على المجلد نفسه. |
| `shutdown.js` | إيقاف منظّم (إيقاف القنوات ثم Nginx). |

## 2. متطلبات النظام

### نظام التشغيل

| المتطلب | التفصيل |
|---|---|
| Windows | **Windows 10 أو 11 (64 بت)** — لأن `ffmpeg.exe` المرفق مبني لمعمارية x64، و`nginx.exe` المرفق نسخة ويندوز 32-بت تعمل على 64-بت أيضًا. |
| بيئة الطرفية | PowerShell (يستخدمه ملف التشغيل لتنظيف عمليات Nginx) — موجود افتراضيًا في Windows 10/11. |
| الصلاحيات | لا يحتاج صلاحيات مدير، إلا إذا رغبت بتشغيل Nginx على منفذ محجوز (انظر المنافذ). |

> يعمل المشروع أيضًا على Linux للتطوير/الاختبار، لكن **الهدف الرسمي هو Windows** (مسار الالتقاط DirectShow).

### Node.js

- **Node.js 18 أو أحدث** (`engines.node: ">=18"` في `package.json`).
- **لا يحتاج أي حزم npm**: `dependencies` فارغة تمامًا، ولا يوجد `node_modules`، ولا اتصال بالإنترنت.
- إن لم يكن Node مثبتًا على الجهاز يمكنك فك نسخة محمولة ووضعها في مجلد `node\` بجانب `server.js` (ملف التشغيل يبحث عن `node\node.exe` أولًا ثم عن `node` في PATH).

### FFmpeg وNginx وffprobe

| الملف | الحالة في المشروع | ملاحظة |
|---|---|---|
| `ffmpeg.exe` | **مرفق** في جذر المشروع (نسخة ويندوز x64) ويُستخدم تلقائيًا. | لمعرفة إصداره: `ffmpeg.exe -version` |
| `nginx/nginx.exe` | **مرفق** (Nginx 1.27.4 لويندوز) مع ملفات `nginx/conf/` المساندة. | `settings.nginxPath` فارغ = استخدم المرفق |
| `ffprobe.exe` | **غير مستخدم وغير مرفق**. | كل قراءات الأجهزة والقدرات تتم عبر `ffmpeg -list_devices` و`-list_options`، لذا لا حاجة لـ ffprobe. |

مسارات البحث الفعلية (من `src/devices.js`):

- إذا كان `settings.ffmpegPath` **مسارًا مطلقًا موجودًا** → يُستخدم.
- وإلا إذا كان **اسمًا** (مثل `ffmpeg`) → يُبحث عنه في `PATH`.
- وإلا يُستخدم `ffmpeg.exe` **بجانب `server.js`**، وإن لم يوجد يُطلب من `PATH`.
- وبالمثل لـ Nginx: `settings.nginxPath` أو `nginx\nginx.exe` المرفق.

### المنافذ

| المنفذ | الوظيفة | المفتاح في الإعدادات | القيمة الافتراضية المرفقة | في هذا التثبيت |
|---|---|---|---|---|
| **3001** | خادم Node (الواجهات + API + قوائم m3u8) | `port` | 3001 | 3001 |
| **801** | Nginx (مقاطع `.ts`) | `nginxPort` | 801 | **80** |

- لا يستخدم البرنامج أي منفذ آخر (FFmpeg لا يستمع على أي منفذ).
- يجب أن يكون المنفذان حرّين؛ البرنامج يرفض حفظ إعدادات تتسبب في تعارض منفذ Nginx مع منفذ النظام.
- عند أول تشغيل قد يطلب Windows Firewall السماح لـ Node/Nginx — اسمح بهما على **الشبكات الخاصة** فقط.

### متطلبات الأجهزة والشبكة

| العنصر | التوصية |
|---|---|
| المعالج | كل قناة مرمَّزة تستهلك نواة أو أكثر. لبطاقة 1080p استخدم 4 أنوية فأكثر، أو اختر «نسخ المصدر» إن كانت الكاميرا تُخرج H.264 أصلاً (بلا ترميز = أخف بكثير). |
| الذاكرة | 4 GB تكفي لبث واحد؛ أضف ~1 GB لكل قناة مضافة. |
| القرص | ملفات HLS دوّارة (عدد محدود من المقاطع)، والكتابة مستمرة: قرص صلب عادي يكفي، ويُفضَّل قرص غير قرص النظام. |
| جهاز الالتقاط | كاميرا USB أو بطاقة التقاط (Capture Card) تظهر لـ DirectShow. بطاقة التقاط HDMI أفضل للجودة والثبات من كاميرا الويب. تجنّب موزّعات USB (Hub) غير المزوّدة بالطاقة. |
| الصوت | إما جهاز صوت في بطاقة الالتقاط، أو ميكروفون/جهاز صوت منفصل — وهو اختياري في المصدر (يمكن الالتقاط بلا صوت). |
| الشبكة | يكفي أن يكون المشاهدون على نفس الشبكة المحلية؛ لا حاجة لإنترنت ولا لإعداد موجّه. من خارج الشبكة يلزم فتح المنافذ/نفق خاص (خارج نطاق هذا المشروع). |

## 3. تثبيت المشروع وتشغيله

### الخطوات بالترتيب

1. **فك الضغط:** انسخ مجلد المشروع إلى مكان دائم، **بمسار بسيط بلا مسافات زائدة أو رموز غريبة** (مثال: `D:\PrinceLive`). تجنّب وضعه داخل `Program Files` أو سطح المكتب المؤقت، لأن مسار المجلد يُكتب داخل `nginx.conf` بمسارات مطلقة.
2. **تثبيت Node.js:** نزّل **Node.js 18 LTS أو أحدث** من الموقع الرسمي وثبّته بالخيارات الافتراضية، أو ضع نسخة محمولة في `node\node.exe` بجانب `server.js`.
   للتأكد: افتح `cmd` واكتب `node -v` — يجب أن يظهر رقم إصدار ≥ 18.
3. **تأكد من الملفات المرفقة:** `ffmpeg.exe` و`nginx\nginx.exe` موجودان داخل مجلد المشروع (يُفحصان تلقائيًا عند التشغيل).
4. **التشغيل:** انقر مزدوجًا على **`تشغيل السيرفر.bat`**. سترى في نافذته:

   ```
   [1/4] Node.js: v22.x.x
   [2/4] ffmpeg.exe: موجود
   [3/4] تجهيز nginx.conf وقراءة المنافذ من الإعدادات...
   العنوانات:
     لوحة التحكم  : http://localhost:801/admin
     صفحة المشاهدين: http://localhost:801/
   ```

   ثم يطبع الخادم سطره الخاص عن Nginx، مثال: `[nginx] Nginx يعمل على المنفذ 801`.

   > **المنافذ التي تراها في هذه الرسائل هي المنافذ الفعلية** المقروءة من `config/config.json` (والقيم الافتراضية 801 و3001). إن غيّرت المنافذ سابقًا فستتغير العناوين تبعًا لذلك.
5. **الدخول إلى لوحة الإدارة:** افتح الرابط المطبوع. الدخول الأول بالحساب المطبوع في نافذة التشغيل (`admin` وكلمة المرور الافتراضية `admin123`) — اللوحة تنبّهك بوجود كلمة مرور افتراضية، **وغيّرها فورًا** من: الإعدادات → كلمة مرور المسؤول.
6. **إضافة مصدر:** من قسم **مصادر البث** → «إضافة مصدر» → اختر النوع (جهاز التقاط / التقاط الشاشة)، واختر جهاز الفيديو (والصوت اختياريًا)، واقرأ قدرات الجهاز الفعلية ثم احفظ. (التفاصيل في [القسم 6](#6-إدارة-القنوات-والبث).)
7. **إنشاء قناة وتشغيلها:** من قسم **القنوات** → «إضافة قناة» → اختر المصدر والجودة والتصنيف، ثم اضغط **تشغيل**. تابع البطاقة: يجب أن تظهر الحالة **مباشر**، وتزداد أرقام المعدل والحجم، وتظهر ملفات جديدة في `srv/hls/<معرّف القناة>/`.
8. **المشاهدة:** افتح `http://localhost:801/` (أو منفذ Node مباشرةً) واختر القناة — يبدأ المشغّل تلقائيًا، وإن كانت القناة متوقفة وكان خيار التشغيل عند الطلب مفعّلًا فستبدأ من تلقاء نفسها.

### ملفا التشغيل

**`تشغيل السيرفر.bat`** — يفعل الآتي بالتسلسل:

1. يتحقق من Node.js (يستخدم `node\node.exe` إن وُجد، وإلا `node` من PATH) ويطبع إصداره.
2. يتحقق من وجود `ffmpeg.exe` (يطبع تنبيهًا إن لم يوجد: `[تنبيه] ffmpeg.exe غير موجود في هذا المجلد — لن يعمل البث`).
3. ينشئ المجلدات الناقصة: `config`, `srv\hls`, `srv\uploads`, `logs`, `run`.
4. يكتب `nginx.conf` من الإعدادات ويقرأ المنافذ الفعلية عبر الأمر `node server.js --write-nginx-conf` (يطبع `NGINX_PORT=…` و`NODE_PORT=…`)، ثم يوقف أي نسخة Nginx قديمة **من مجلد المشروع فقط** (بالتحقق من مسار الملف التنفيذي).
5. يطبع العناوين ثم يشغّل `node server.js` (وهو بدوره يشغّل Nginx ويتحقق من المنفذ).
6. عند إيقاف الخادم (Ctrl+C أو إغلاق النافذة) يُغلق Nginx الخاص بالمشروع، ولا يلمس أي Node أو Nginx آخر على الجهاز.

**`ايقاف السيرفر.bat`** — للإيقاف الكامل بعد إغلاق نافذة التشغيل أو تعليقها:

1. يرسل إشارة إيقاف إلى Nginx من مجلد المشروع (`nginx.exe -p . -c conf\nginx.conf -s stop`)، ثم ينظّف أي عمليات `nginx.exe` تشير مساراتها التنفيذية إلى مجلد المشروع فقط.
2. يقرأ `run\server.lock` ويوقف **خادم Node الذي يحمل المعرّف المسجَّل فيه** فقط (يتحقق من أن اسم العملية `node.exe` وأن سطر الأوامر يحتوي `server.js`) — فلا يُلمس أي Node آخر على الجهاز.

### التأكد من أن الخدمات تعمل

| ما تتحقق منه | كيف |
|---|---|
| الخادم يعمل | افتح `http://localhost:3001/api/ping` → يجب أن يظهر `{"ok":true,...}` |
| Nginx يعمل | في لوحة التحكم: قسم **المراقبة والسجلات** → بطاقة «Nginx» (تعرض المنفذ)، أو `http://localhost:3001/api/nginx/status` |
| البث يُنتَج فعلاً | قائمة المقاطع في `srv\hls\<معرّف القناة>\` يجب أن تتغير كل ثانيتين (`hlsTime`), وتظهر حالة القناة **مباشر** |
| المشاهدون يرون البث | افتح صفحة المشاهدين من جهاز آخر على الشبكة: `http://<IP-الجهاز>:801/` |
| الإعدادات سليمة | لوحة التحكم → **الإعدادات** ثم أعد التشغيل وتأكد من بقاء القيم |

### أوامر مفيدة (من داخل مجلد المشروع)

```bat
node server.js                     :: تشغيل الخادم في الطرفية (بدون ملف الـ bat)
node server.js --write-nginx-conf  :: إعادة توليد nginx.conf وطباعة أرقام المنافذ فقط
npm test                           :: تشغيل الاختبارات (24 اختبارًا، وهي لا تحتاج إنترنت)
node --test tests\router.test.js   :: اختبار واحد فقط
```

## 4. شرح ملف config.json

### الموقع ودورة الحياة

- الملف الفعلي: **`config\config.json`** (بجانب المشروع، وليس في أي مكان آخر).
- **لا تُرفع/تُوزَّع** نسخة هذا الملف؛ فهي تحتوي تجزئة كلمة المرور ومفتاح توقيع الجلسة وبيانات قنواتك.
- عند **أول تشغيل** يُنشأ `config.json` من `config\config.default.json` (الملف المرفق والمقصود توزيعه).
- عند التشغيل التالي: تُدمج القيم المحفوظة فوق القيم الافتراضية **لكل مفتاح على حدة**، وأي مفتاح جديد يُضاف في `config.default.json` يظهر تلقائيًا في إعداداتك دون فقدان قيمك (`mergeDefaults` في `src/store.js`).
- تُحفظ التغييرات **كتابة ذرّية** (ملف مؤقت ثم استبدال) لتقليل خطر تلف الملف، وإن كان الملف تالفًا يحتفظ البرنامج بنسخة منه باسم `config.json.broken-<رقم الوقت>` ويبدأ بالإعدادات الافتراضية بدل فقدانه.
- إذا حُذف `hash`/`salt` (كلمة المرور) يعيد البرنامج إنشاء كلمة المرور الأولية عند التشغيل التالي (`admin123` أو قيمة المتغير `AMAAN_INITIAL_PASSWORD` إن ضبطته).

### البنية العامة

```
config.json
├─ settings   { ... }   الإعدادات العامة (الجدول أدناه)
├─ admin      { user, salt, hash, passwordIsDefault }   حساب المسؤول (تجزئة فقط، بلا كلمة مرور صريحة)
├─ session    { secret }   مفتاح توقيع الجلسات (يُولَّد مرة واحدة)
├─ sources    [ ... ]   مصادر الالتقاط
├─ channels   [ ... ]   القنوات
└─ ads        [ ... ]   الإعلانات
```

### خيارات `settings` الفعلية

القيم التالية هي **القيم الافتراضية المرفقة** في `config.default.json`:

| المفتاح | الافتراضي | الوظيفة |
|---|---|---|
| `siteName` | بثي المحلي | اسم الموقع الظاهر للمشاهدين وفي اللوحة |
| `siteNameLatin` | My Live | الاسم اللاتيني أسفل الشعار |
| `logo` | `logo.png` | ملف شعار صفحة المشاهدين (من `public/viewer/`) |
| `phone` | (فارغ) | رقم هاتف يظهر للمشاهدين — اتركه فارغًا لإخفائه |
| `ticker` | أهلاً بكم في البث المباشر | نص الشريط المتحرك |
| `tickerEnabled` | true | إظهار/إخفاء الشريط المتحرك |
| `port` | 3001 | منفذ خادم Node (الواجهات وAPI وقوائم m3u8) |
| `nginxPort` | 801 | منفذ Nginx الذي يخدم مقاطع `.ts` |

| `x264Threads` | 2 | عدد خيوط الترميز (0/فارغ = تلقائي) |
| `audioBitrate` | 128k | معدل بت الصوت (AAC بمعدل عينات 44100) |
| `startupQueueDelayMs` | 4000 | فاصل زمني بين تشغيل قناة وأخرى عند إقلاع البرنامج |
| `startupConcurrency` | 1 | عدد القنوات التي تُشغَّل في الوقت نفسه عند الإقلاع |
| `autoRestartCrashed` | true | إعادة تشغيل القناة تلقائيًا عند تعطل FFmpeg |
| `restartBackoffMs` | 5000 | زمن الانتظار قبل محاولة الإعادة التالية |
| `maxRestarts` | 20 | أقصى عدد محاولات إعادة تشغيل للقناة |
| `logMaxLines` | 800 | أقصى عدد أسطر محفوظة في سجل كل قناة |

| `autoStartOnDemand` | true | **تشغيل القناة تلقائيًا عند طلب مشاهد**: يبدأ البث فورًا عند فتح المشاهد قناةً متوقفة (بدل انتظار ضغط «تشغيل» في اللوحة) |
| `viewerWindowSeconds` | 20 | نافذة احتساب المشاهد: من قرأ مقطعًا خلالها يُعدّ مشاهدًا الآن |
| `deviceWatchSeconds` | 5 | فاصل فحص اتصال أجهزة الالتقاط |
| `sourceFailStopMinutes` | 3 | إيقاف القناة بعد هذه المدة إن بقي مصدرها فاشلاً |
| `playerMaxBufferLength` | 20 | أقصى مخزون مؤقت في مشغّل المشاهد (ثوانٍ) |

| `cpuSaverDefault` | true | تفعيل «توفير المعالج» في مشغّل المشاهد افتراضيًا (يقلّل المخزون إلى 10 ث كحد أقصى) |
| `logoImage` | (فارغ) | صورة شعار مائي مرفوعة (تُحفظ في `srv/uploads/`) |
| `logoPosition` | top-right | موضع الشعار: `top-right`, `top-left`, `bottom-right`, `bottom-left`, `center` |

### بنية المصادر والقنوات والإعلانات

**المصدر (`sources[]`):**

| الحقل | المعنى |
|---|---|
| `id`, `name`, `createdAt` | المعرّف والاسم وتاريخ الإنشاء |
| `type` | `usb` (جهاز التقاط DirectShow) أو `screen` (التقاط الشاشة) |
| `videoDevice`, `audioDevice` | اسما جهاز الفيديو والصوت كما يظهران لـ DirectShow (الصوت اختياري) |
| `videoSize`, `fps` | الدقة ومعدل الإطارات (لجهاز الالتقاط: من قدرات الجهاز؛ وللشاشة: مثل `1280x720` و15) |
| `pixelFormat` | صيغة الالتقاط (مثل `mjpeg`, `yuyv422`) من القدرات الفعلية للجهاز |
| `captureSafeMode` | وضع الالتقاط الآمن: لا يُفرض دقة/معدل إطارات — للكاميرات الحساسة |
| `notes` | ملاحظات حرة |

**القناة (`channels[]`):**

| الحقل | المعنى |
|---|---|
| `id`, `name`, `createdAt`, `sort` | المعرّف والاسم وترتيب الظهور |
| `sourceId` | المصدر المرتبط |
| `category` | تصنيف يظهر كفلتر في صفحة المشاهدين |
| `cover` | صورة غلاف (اختيارية) |
| `enabled` | إن كانت معطّلة فلا تظهر للمشاهدين ولا تُشغَّل |
| `autoStart` | تُشغَّل تلقائيًا عند إقلاع البرنامج |
| `manualStopped` | أُوقفت يدويًا من اللوحة → لا يشملها التشغيل التلقائي حتى تضغط «تشغيل» |
| `quality` | `copy` (بلا ترميز) أو `240p`/`360p`/`480p`/`720p`/`1080p` |
| `fps`, `threads` | تجاوز اختياري لمعدل الإطارات وعدد الخيوط لهذه القناة (فراغ = إعدادات عامة) |
| `schedule` | `{ enabled, days:[0..6], from:"HH:MM", to:"HH:MM" }` |

**الإعلان (`ads[]`):** `type` = `text` (يظهر في الشريط المتحرك) أو `image` (سلايدر أسفل الترويسة)، مع `text` أو `image` و`enabled`.

### تعديل الإعدادات بأمان

1. **الطريقة المفضلة:** من لوحة التحكم → قسم **الإعدادات** → غيّر القيم → **حفظ**. البرنامج يتحقق من القيم (مثل تعارض منافذ Nginx/Node وحدود الأرقام) ويرفض غير الصالح منها برسالة واضحة.
2. **قبل أي تعديل يدوي (خارج اللوحة): خُذ نسخة احتياطية** — انسخ `config\config.json` إلى مكان آمن وباسم يحتوي التاريخ (مثال: `config-2026-10-22.json`).
3. **أوقف الخادم أولاً** (نفّذ `ايقاف السيرفر.bat` أو Ctrl+C) قبل تحرير الملف يدويًا، ثم أعد التشغيل ليُقرأ الملف من جديد.
4. حافظ على **صيغة JSON الصحيحة**: بلا فواصل زائدة، وبعلامات اقتباس مزدوجة للأسماء والقيم النصية، وبلا تعليقات. أي خطأ يعني بدء البرنامج بالإعدادات الافتراضية مع الاحتفاظ بنسخة `config.json.broken-<رقم>` (يمكنك تصحيحها واستعادتها).
5. المفاتيح التي **لا** يجب أن تتجاوزها الحدود المنطقية: `hlsTime` (1–10 ث تقريبًا)، `hlsListSize` > `hlsDeleteThreshold`، أرقام المنافذ بين 1024 و65535 (الأفضل تجنّب المنافذ المحجوزة)، `x264Threads` لا تتجاوز عدد أنوية المعالج.
6. **بعد تغيير المنافذ أو مسارات Nginx**: أعد توليد ملف Nginx من اللوحة (زر إعادة توليد إعداد Nginx) أو نفّذ `node server.js --write-nginx-conf`، ثم أعد تشغيل Nginx، لأن `nginx.conf` يحتوي المسارات المطلقة ورقم المنفذ.
7. عند تعديل إعدادات البث (`hlsTime`, `quality`, `x264Preset`, `x264Threads`, `audioBitrate`, `gopSeconds`) **أعد تشغيل القناة** ليُطبَّق الإعداد الجديد، فالعملية تعمل بالوسائط التي بدأت بها.

## 5. روابط الوصول السريع

القيم أدناه مأخوذة من مفاتيح الإعدادات الفعلية: `port = 3001` و`nginxPort = 801` (الافتراضي المرفق). إن غيّرت المنافذ من الإعدادات فاستبدلها في العناوين.

| الوجهة | عبر Nginx | عبر Node مباشرةً |
|---|---|---|
| **لوحة الإدارة والتحكم** | `http://localhost:801/admin` | `http://localhost:3001/admin` |
| **صفحة المشاهدين** | `http://localhost:801/` | `http://localhost:3001/` |
| مقطع بث قناة (m3u8) | `http://localhost:801/hls/<معرّف القناة>/index.m3u8` | `http://localhost:3001/hls/<معرّف القناة>/index.m3u8` |
| المرفوعات (شعار/أغلفة) | `http://localhost:801/uploads/<اسم الملف>` | `http://localhost:3001/uploads/<اسم الملف>` |
| مكتبة المشغّل المحلية | `http://localhost:801/vendor/hls.min.js` | `http://localhost:3001/vendor/hls.min.js` |

**للمشاهدين على أجهزة أخرى في الشبكة المحلية:** استبدل `localhost` بمعرّف IP لجهاز البث، مثال: `http://192.168.1.50:801/` (اعرف الـ IP بالأمر `ipconfig`).

واجهات API موجودة فعلاً (أهمّها):

| المسار | الوصف |
|---|---|
| `GET /api/ping` | فحص سريع: `{"ok":true,...}` |
| `POST /api/login` / `POST /api/logout` / `GET /api/me` | الدخول والخروج وحالة الجلسة |
| `GET /api/settings` · `PUT /api/settings` · `POST /api/settings/password` | قراءة/حفظ الإعدادات وتغيير كلمة المرور |
| `POST /api/settings/regenerate-nginx` | إعادة توليد `nginx.conf` |
| `GET /api/nginx/status` · `POST /api/nginx/start|stop|reload` | حالة Nginx والتحكم به |
| `GET /api/stats` | إحصاءات اللوحة (قنوات، مشاهدون، باندويث، معالج) |
| `GET /api/devices` · `POST /api/devices/scan` · `GET /api/devices/diagnose` · `POST /api/devices/test` | اكتشاف الأجهزة وتشخيصها واختبار الالتقاط |
| `GET/POST/PUT /api/sources` | إدارة مصادر الالتقاط |
| `GET/POST/PUT /api/channels` · `POST /api/channels/:id/start|stop|restart` · `GET /api/channels/:id/log` | إدارة القنوات وحالتها وسجلاتها |
| `GET/POST/PUT/DELETE /api/ads` | إدارة الإعلانات |
| `POST /api/upload` | رفع الشعار/الغلاف (multipart، بحدّ 12 ميغابايت) إلى `srv/uploads/` |
| `GET /api/public/settings` · `GET /api/public/channels` | بيانات عامة لصفحة المشاهدين (بلا مصادقة) |
| `GET /api/public/channel-health?id=<id>` | حالة قناة ومشاهدوها (بلا مصادقة) |
| `POST /api/public/watch` | طلب مشاهدة من صفحة المشاهدين (يشغّل القناة عند الطلب) |

> كل مسارات `/api/*` الأخرى محمية بجلسة المسؤول. الصفحات العامة للجمهور هي صفحة المشاهدين فقط.

## 6. إدارة القنوات والبث

### 6.1 اكتشاف أجهزة الفيديو والصوت

من **مصادر البث** → «إضافة مصدر»:

1. اضغط زر فحص الأجهزة (يقرأ البرنامج `ffmpeg -list_devices true -f dshow -i dummy`).
2. اختر **جهاز الفيديو** من القائمة، واختر **جهاز الصوت** إن أردت الصوت (اختياري).
3. عند اختيار جهاز يقرأ البرنامج قدراته الفعلية مباشرةً من الجهاز (`ffmpeg -f dshow -list_options true -i video="..."`)، فتظهر **الدقة ومعدل الإطارات وصيغة الالتقاط الحقيقية** — لا قوائم ثابتة ولا أجهزة وهمية.
4. استخدم **«🎥 اختبار الالتقاط»** للتأكد من أن الجهاز يعمل فعلاً قبل حفظ المصدر.

**مصدر الشاشة:** بدّل النوع إلى «التقاط الشاشة» وحدّد الدقة ومعدل الإطارات (افتراضيًا `1280x720` و15) — مفيد للعروض والاختبار بلا كاميرا.

### 6.2 إعداد المصادر

| الإعداد | متى تستخدمه |
|---|---|
| الدقة / معدل الإطارات | اختر من القدرات التي طبعها الجهاز، ولا تكتب قيمة غير مدعومة |
| صيغة الالتقاط | `mjpeg` غالبًا أخف وأنسب لكاميرات الويب، و`yuyv422` أقل ضغطًا وأثقل على USB |
| **وضع الالتقاط الآمن** | فعّله للكاميرات الحساسة التي تفشل عند فرض دقة/معدل: يترك الجهاز بإعداداته الافتراضية |
| الاسم/الملاحظات | للتمييز بين مصادر متعددة متصلة في الوقت نفسه |

### 6.3 إنشاء القنوات

من **القنوات** → «إضافة قناة»: اسم القناة، المصدر، التصنيف، الغلاف (اختياري)، ثم خصائص البث:

- **الجودة:** `copy` = «نسخ المصدر بلا ترميز» (الأخف على المعالج؛ إن كانت الكاميرا تُخرج H.264)، أو `240p` … `1080p` (يُقاس الارتفاع ويُحسب معدل البت تلقائيًا).
- **معدل الإطارات والخيوط:** تجاوز اختياري لإعدادات القناة العامة (فراغ = القيم العامة).
- **الجدولة:** نافذة أيام/ساعات اختيارية (تدعم النوافذ التي تعبر منتصف الليل).
- **التشغيل التلقائي عند الإقلاع (`autoStart`)** لمن تريد أن يعمل دائمًا.
- **مفعّلة (`enabled`)** لظهورها للمشاهدين.

### 6.4 التشغيل والإيقاف والمراقبة

- **تشغيل:** زر «تشغيل» في بطاقة القناة → الحالة تصبح «مباشر» بعد ثوانٍ (`startupQueueDelayMs` عند إقلاع عدة قنوات).
- **إيقاف:** زر «إيقاف» → تُوسم القناة بأنها موقوفة يدويًا فلا يعيدها التشغيل التلقائي حتى تضغط «تشغيل» (أو تفعّل التشغيل عند الطلب، مع الضغط على تشغيل مرة).
- **إعادة تشغيل:** زر «إعادة تشغيل القناة» في اللوحة وبطاقة القناة (يصفّر عدّاد الإعادات).
- **المراقبة:** قسم «المراقبة والسجلات» يعرض لكل قناة: الحالة، المشاهدين الآن، معدل الإطارات الداخل، معدل البت، المقاسات/التقدم، الإطارات المفقودة، حجم الخرج، عدد الإعادات التلقائية، وآخر خطأ. وتُعرض أيضًا: حالة Nginx، المعالج، باندويث الخروج، و«إجمالي المشاهدين» منذ إقلاع البرنامج.
- **إعادة التشغيل التلقائية:** عند تعطل العملية أو تجمّدها (قائمة HLS لا تُحدَّث لمدة = خمسة أضعاف مدة المقطع بحدّ أدنى 10 ثوانٍ) تُعاد القناة تلقائيًا باحترام `maxRestarts` و`restartBackoffMs`، وإن كان `autoRestartCrashed` معطّلًا فلا إعادة.

### 6.5 المشاهدة من صفحة المشاهدين

- المستخدم يفتح `http://<IP>:801/` → قائمة القنوات (مع التصنيفات والغلاف)، ويختار قناة → يُبنى الطلب على `/hls/<id>/index.m3u8` عبر `hls.js` المحلي.
- عناصر الصفحة: الشريط المتحرك (إن كان مفعّلاً)، الإعلانات، شعار الموقع، رقم الهاتف (إن كُتب)، وإعداد «توفير المعالج» في المشغّل.
- كل قراءة لقائمة أو مقطع تُحتسب مشاهدة، ويظهر العدد في اللوحة وبطاقة القناة.

### 6.6 التشغيل التلقائي عند طلب مشاهد

1. المشاهد يختار قناة متوقفة من صفحة المشاهدين.
2. الصفحة ترسل `POST /api/public/watch` مع معرّف القناة.
3. البرنامج يعمل بالترتيب: إن كانت القناة **معطّلة** أو **موقوفة يدويًا** → لا شيء؛ وإن كانت **تعمل** → لا شيء؛ وإن كان خيار **«تشغيل القناة تلقائيًا عند طلب مشاهد» معطّلًا** → لا شيء (`reason: disabled`)؛ وإن كنا **خارج نافذة جدولتها** → لا شيء (`reason: scheduled`)؛ وإلا يبدأ FFmpeg وتعود النتيجة `started: true`.
4. صفحة المشاهدين تستمر بمراقبة الحالة حتى يصبح البث جاهزًا ثم يعمل المشغّل.
5. عند الخمول لاحقًا (`idleStopMinutes`) تُوقف القناة تلقائيًا، ويعيدها طلب المشاهد التالي — فتبقى القنوات جاهزة بلا استهلاك دائم للمعالج.
6. **التفعيل/التعطيل:** الإعدادات → «تشغيل القناة تلقائيًا عند طلب مشاهد». القيمة الافتراضية للمفتاح `autoStartOnDemand` في `config.default.json` هي `true` (مفعّل)، وما تغيّره في اللوحة يُحفظ في `config.json` ويُطبَّق على الطلبات التالية مباشرةً بلا إعادة تشغيل البرنامج.
7. **علاقته بـ `autoStart`:** لا تكرار بينهما — `autoStart` خيار **لكل قناة** يعني «ابدأ عند إقلاع البرنامج»، أما `autoStartOnDemand` فإعداد **عام واحد** يعني «ابدأ عند طلب مشاهد لقناة متوقفة». ويبقى شرط القناة المطلوبة أن تكون مفعّلة وغير موقوفة يدويًا وداخل نافذة جدولتها.

### 6.7 الإيقاف التلقائي عند الخمول

- يُشغَّل إن كان `idleStopEnabled = true`: كل دورة، تُفحص كل قناة عاملة؛ فإذا لم يكن لها **أي قراءة HLS** خلال `idleStopMinutes` (المشاهد يُحتسب إن قرأ خلال `viewerWindowSeconds`)، تُوقف القناة ويُسجَّل السبب.
- **مهم:** التبويب المخفي لا علاقة له بالحساب؛ المشاهد يُحتسب طالما المشغّل يواصل قراءة المقاطع. أما إذا أوقف المشاهد التشغيل مؤقتًا (Pause) أو أغلق الصفحة فسيتوقف عن القراءة وبالتالي يُعدّ خاملًا بعد انتهاء المهلة.
- لتعطيل الميزة: الإعدادات → «إيقاف القناة عند خمول المشاهدين» ← أطفئها.

### 6.8 السجلات وتشخيص الأخطاء

| السجل | المكان | ما يفيدك فيه |
|---|---|---|
| سجل القناة | `logs\channel-<id>.log` (ويظهر في اللوحة) | مخرجات FFmpeg الحقيقية: سبب رفض الجهاز، انقطاع الإدخال، أخطاء الترميز |
| سجل Nginx | `nginx\logs\error.log` | فشل تشغيل Nginx، تعارض المنافذ، أخطاء المسارات |
| سجل الوصول | `nginx\logs\access.log` | قراءات مقاطع `.ts` (يُستخدم أيضًا لعدّ المشاهدين) |
| حالة الخادم | نافذة `تشغيل السيرفر.bat` | رسائل التشغيل: `[nginx] ...`, `[watch] تشغيل «...» عند طلب مشاهد` |
| التشخيص في اللوحة | مصادر البث → تشخيص الأجهزة | سبب عدم ظهور الجهاز ومسار ffmpeg المستخدم |

تصنيف الأسطر المهمّة في سجل القناة: الأسطر المتعلقة بـ`could not find` / `no such device` / `Device or resource busy` / `Permission denied` هي أخطاء عالية الأثر على القناة، و`timed out` / `will reconnect` أخطاء شبكة/جهاز متوسطة، و`drop` / `late` / `queue` مشاكل أداء منخفضة الأثر.

## 7. استكشاف الأخطاء وإصلاحها

### 7.1 فشل تشغيل FFmpeg

- **الظهور:** نافذة التشغيل تطبع `[تنبيه] ffmpeg.exe غير موجود في هذا المجلد — لن يعمل البث`، أو فشل الالتقاط في اللوحة.
- **الأسباب:** `ffmpeg.exe` غير موجود بجانب المشروع، أو `settings.ffmpegPath` يشير إلى مسار خاطئ/غير قابل للتشغيل، أو نسخة ffmpeg قديمة لا تدعم DirectShow (يعرض البرنامج رسالة: «نسخة ffmpeg هذه لا تدعم DirectShow (dshow)»).
- **الحل:** أعِد `ffmpeg.exe` المرفق إلى جذر المشروع، أو امسح `ffmpegPath` ليعود للنسخة المرفقة، وتأكد أن النسخة 64-بت ولا تحتاج مكتبات ناقصة. تحقق يدويًا:

  ```bat
  ffmpeg.exe -version
  ffmpeg.exe -list_devices true -f dshow -i dummy
  ```

### 7.2 عدم اكتشاف كاميرا أو جهاز التقاط

- **الظهور:** قائمة أجهزة الفيديو فارغة في «إضافة مصدر»، أو رسالة `Could not find video device with name ...`.
- **الأسباب:** الجهاز مستخدم من تطبيق آخر (Zoom/Teams/برنامج كاميرا)، أو صلاحية الكاميرا مغلقة لنظام Windows، أو كابل/موزّع USB ضعيف، أو الجهاز لا يدعم DirectShow.
- **التشخيص والحل:**
  1. أغلق كل برنامج يستخدم الكاميرا، ثم أعد الفحص من اللوحة.
  2. تحقق من: الإعدادات → الخصوصية والأمان → الكاميرا → «السماح لتطبيقات سطح المكتب بالوصول إلى الكاميرا» (وكذلك الميكروفون للصوت).
  3. جرّب منفذ USB مباشرًا على اللوحة الخلفية، ويفضّل USB 3.0 لبطاقات الالتقاط.
  4. شغّل الأمر `ffmpeg.exe -list_devices true -f dshow -i dummy` وراجع الأسماء كما تظهر تمامًا.
  5. إن ظهرت قائمة أجهزة طويلة (كبعض كاميرات الأمان) فانتظر ثوانٍ حتى ينتهي الفحص ثم أعد المحاولة.

### 7.3 عدم اكتشاف أجهزة الصوت

- **الظهور:** قائمة الصوت فارغة أو لا صوت في البث.
- **الأسباب:** الجهاز صامت أو معطّل في «إدارة الأجهزة»، أو مستوى الصوت صفر/كتم، أو بطاقة الالتقاط لا تنقل الصوت (تحتاج مدخل صوت منفصل)، أو الصوت محجوز لتطبيق آخر.
- **الحل:** استخدم قائمة الصوت في نموذج المصدر بعد إعادة الفحص، أو اترك حقل الصوت فارغًا لالتقاط الفيديو فقط (`بلا جهاز صوت` مدعوم ومُختبَر في الكود). تأكد من مستوى الإدخال من إعدادات Windows → الصوت → الإدخال، وارفع مستوى الالتقاط.

### 7.4 تعارض المنافذ

- **الظهور:** فشل تشغيل Nginx مع رسالة تشخيص للمنفذ، أو رفض حفظ الإعدادات، أو صفحة لا تُفتح.
- **الأسباب:** برنامج آخر يستخدم المنفذ (IIS على 80، برامج مزامنة، نسخة سابقة من التطبيق لم تُغلق).
- **التشخيص والحل:**

  ```bat
  netstat -ano | findstr :801
  netstat -ano | findstr :3001
  tasklist | findstr /i "node nginx"
  ```

  ثم: أوقف البرنامج المتعارض، أو غيّر المنفذ من الإعدادات (ويُفضَّل استخدام 801 لـ Nginx و3001 لـ Node)، ثم أعد توليد `nginx.conf` وأعد تشغيل Nginx. تأكد أن نسختك القديمة أُغلقت بـ`ايقاف السيرفر.bat`. البرنامج يمنع حفظ إعدادات تجعل منفذ Nginx مطابقًا لمنفذ Node.

### 7.5 فشل تشغيل Nginx

- **الظهور:** `[nginx] تعذّر تشغيل Nginx...` في نافذة التشغيل، وبطاقة Nginx في اللوحة لا تقول «يعمل».
- **الأسباب:** المنفذ مستخدم، أو `nginx.conf` يشير إلى مسارات غير موجودة (بعد نقل المجلد)، أو ملف مضاد للفيروسات منع التنفيذ، أو مشكلة في `mime.types`.
- **التشخيص والحل:**
  1. اقرأ `nginx\logs\error.log` — يسمّي السبب بدقة.
  2. شغّل Nginx يدويًا لرؤية الأخطاء على الشاشة:

     ```bat
     cd nginx
     nginx.exe -p . -c conf\nginx.conf
     ```

  3. إن نقلت مجلد المشروع: أعد توليد الإعداد (`node server.js --write-nginx-conf` أو الزر في اللوحة) لأن الملف يحتوي مسارات مطلقة.
  4. إن كان المنفذ 80 محجوزًا (IIS/خدمة أخرى): غيّره إلى 801 من الإعدادات.
  5. **يمكنك العمل بلا Nginx مؤقتًا:** أطفئ «تشغيل Nginx مع البرنامج» وستُقدَّم كل الملفات من Node على المنفذ 3001 (أبطأ قليلًا لكنه يعمل).

### 7.6 عدم إنشاء ملفات HLS أو عدم تحديثها

- **الظهور:** مجلد `srv\hls\<معرّف القناة>\` فارغ أو `index.m3u8` لا يتغير.
- **الأسباب:** القناة لم تُشغَّل أصلاً، أو فشل الالتقاط (جهاز مشغول)، أو امتلاء القرص، أو خطأ في الوسائط (دقة/صيغة غير مدعومة).
- **التشخيص والحل:**
  1. تأكد أن حالة القناة **مباشر** (لا «متوقفة» ولا «بانتظار الجهاز»).
  2. افتح سجل القناة وقارن آخر سطر بوقت الآن — إن لم يتغير شيء فالعملية متوقفة أصلاً.
  3. تحقق من مساحة القرص، ومن أن `hlsRoot` يشير إلى مجلد قابل للكتابة.
  4. جرّب جودة `copy` مؤقتًا لتحديد ما إذا كانت المشكلة في الترميز أم في الالتقاط.
  5. أول مقطع يظهر بعد `hlsTime` ثانية من بدء القناة — انتظر ثانيتين قبل الحكم.

### 7.7 ظهور «القناة متوقفة» عند طلب المشاهدة

- **الأسباب المحتملة (بالترتيب):**
  | السبب | كيف تتحقق |
  |---|---|
  | خيار التشغيل عند الطلب معطّل (`autoStartOnDemand`) | الإعدادات → «تشغيل القناة تلقائيًا عند طلب مشاهد» (الافتراضي في التثبيت الجديد: مفعّل) |
  | القناة موقوفة يدويًا | بطاقة القناة تقول «متوقفة» بعد إيقاف يدوي → اضغط «تشغيل» لتسمح بالتشغيل التلقائي بعدها |
  | القناة معطّلة | القنوات → «مفعّلة» |
  | خارج نافذة الجدولة | الجدولة → أيام/ساعات القناة |
  | لم يظهر المصدر أو الجهاز | مصدر القناة صحيح؟ والشاشة: «تشخيص الأجهزة» |
- **ملاحظة:** ردّ الواجهة يوضّح السبب فعليًا: `stopped` / `disabled` / `scheduled` / `error` (مع رسالة الخطأ) — راجع سجل الخادم لسطر `[watch] ...`.

### 7.8 فشل التشغيل التلقائي للقناة

- تأكد أن `autoStart = true` للقناة، وأنها `enabled`، وأنها ليست موقوفة يدويًا — التشغيل عند الإقلاع يمرّ على القنوات التي تحقق هذه الشروط فقط، مع فاصل `startupQueueDelayMs` بين قناة وأخرى وتزامن `startupConcurrency`.
- إن كانت القناة تعمل ثم توقفت واستُنفدت محاولات الإعادة (`maxRestarts`) فلن تُعاد تلقائيًا؛ راجع «عدد الإعادات» في اللوحة ثم اضغط «تشغيل».
- إن كان المصدر فاشلاً أكثر من `sourceFailStopMinutes` تُوقف القناة بانتظار تدخلك.

### 7.9 انقطاع الصورة أو الصوت

- **الأسباب:** الترميز أثقل من طاقة المعالج (خصوصًا 1080p بـ`slow`)، أو USB لا يتحمل تدفقًا غير مضغوط (`yuyv422` بدقة عالية)، أو ضعف تغذية الجهاز، أو جهاز مشترك مع تطبيق آخر.
- **الحل:**
  1. خفّض الجودة (720p ← 480p) أو استخدم `copy` إن كانت الكاميرا تُخرج H.264.
  2. ارفع سرعة إعداد x264 (`veryfast` أو `ultrafast`) وقلّل `x264Threads` إن كان المعالج مشبعًا (لا ترفعه فوق عدد الأنوية).
  3. اختر `mjpeg` بدل `yuyv422` لتخفيف ضغط USB.
  4. راقب في اللوحة: معدل الإطارات الداخل، الإطارات المفقودة، وحمل المعالج — الثبات أهم من الجودة.
  5. راجع سجل القناة: تكرار `timed out` / `Device or resource busy` يعني مشكلة جهاز لا مشكلة إعداد.

### 7.10 توقف القناة بعد انتهاء مدة الخمول

سلوك مقصود عند تفعيل `idleStopEnabled`؛ الأسباب والحلول:

| الحالة | الحل |
|---|---|
| لا مشاهدون فعليًا | هذا هو الهدف من الميزة: توفير المعالج. يعيدها طلب المشاهد التالي (مع التشغيل عند الطلب). |
| المشاهد يوقف التشغيل مؤقتًا (Pause) فلا يقرأ مقاطع | يعدّ البرنامج ذلك خمولًا (لا قراءات HLS). |
| مهلة قصيرة جدًا | ارفع `idleStopMinutes` (مثلاً 5 أو 10 دقائق). |
| تريد تعطيلها كليًا | الإعدادات → أطفئ «إيقاف القناة عند خمول المشاهدين». |

### 7.11 تعذّر الوصول إلى لوحة الإدارة

1. تأكد أن نافذة `تشغيل السيرفر.bat` ما زالت مفتوحة والبرنامج يعمل (إغلاق النافذة يُوقف الخادم — وأمر الإيقاف من اللوحة متاح أيضًا).
2. تأكد من المنفذ الصحيح: 801 (Nginx) و3001 (Node). جرّب الرابط المباشر `http://localhost:3001/admin` — إن فتح فهو يعمل وNginx وحده هو المتوقف.
3. افحص: `http://localhost:3001/api/ping`؛ إن لم يستجب فالخادم متوقف — أعد `تشغيل السيرفر.bat` واقرأ رسائل الخطأ.
4. إن كنت تدخل من جهاز آخر: استخدم IP جهاز البث لا `localhost`، وتأكد من السماح في Windows Firewall على الشبكة الخاصة.
5. إن ظهرت صفحة الدخول لكنها ترفض كلمة المرور: راجع [القسم 8](#8-الأمان-والنسخ-الاحتياطي) (استعادة الحساب).
6. إن كان المنفذ محجوزًا: انظر [7.4](#74-تعارض-المنافذ).

### 7.12 فقدان الإعدادات أو أخطاء مسارات الملفات

- **فقدان الإعدادات:** إن كان `config.json` تالفًا يبدأ البرنامج بالإعدادات الافتراضية ويحفظ نسخة باسم `config\config.json.broken-<رقم الوقت>` — استعد منها يدويًا ما تحتاجه، أو من نسختك الاحتياطية.
- **«ملف غير موجود» / فشل مسارات:** كل المسارات المهمة نسبةً إلى مجلد المشروع (`srv/hls`, `srv/uploads`, `logs`, `run`) وتُنشأ تلقائيًا؛ إن كانت ناقصة أوقف البرنامج ثم شغّله (أو نفّذ `تشغيل السيرفر.bat` الذي ينشئها).
- **بعد نقل مجلد المشروع** إلى مسار آخر: أعد توليد `nginx.conf` (مسارات مطلقة)، وتأكد من أنك لا تشغّل نسختين من المجلد نفسه في الوقت ذاته (يمنعه قفل `run/server.lock`).

## 8. الأمان والنسخ الاحتياطي

### حماية الدخول

- اللوحة محمية بحساب مسؤول واحد، وكلمة المرور مخزّنة **كتجزئة scrypt** (`N=16384, r=8, p=1`, مخرج 32 بايت) مع `salt` عشوائي — لا تُحفظ الكلمة صريحة أبدًا.
- جلستك تُحفظ في **كوكي موقّع بـHMAC-SHA256** بمفتاح داخل `config.json`، وصالح لـ **12 ساعة**، ويُفقد عند الخروج.
- الدخول الأول `admin` / `admin123` (الافتراضي المرفق)، واللوحة تعرض تحذيرًا ما دامت كلمة المرور الافتراضية مستخدمة. **غيّرها فورًا** من: الإعدادات → كلمة مرور المسؤول (يمكن أيضًا ضبط كلمة أولية عند التثبيت عبر متغير البيئة `AMAAN_INITIAL_PASSWORD`).
- لا تفتح لوحة الإدارة ولا منافذ التطبيق للإنترنت؛ الاستخدام المقصود شبكة محلية موثوقة.

### النسخ الاحتياطي

| ما تنسخه | الملف/المجلد | لماذا |
|---|---|---|
| **الأهم** | `config\config.json` | كل شيء: الإعدادات والقنوات والمصادر والإعلانات وتجزئة كلمة المرور ومفتاح الجلسة |
| استحسانًا | `srv\uploads\` | الشعار المائي والأغلفة والصورة المرفوعة |
| عند الحاجة | `public\viewer\logo.png` | شعار صفحة المشاهدين إن عدّلته |
| لا حاجة لنسخه | `srv\hls\`, `logs\`, `run\`, `nginx\logs\` | بيانات تشغيل تُنشأ من جديد |

**الطريقة:**

1. أوقف التطبيق (`ايقاف السيرفر.bat` أو Ctrl+C) — حتى لا تصفّ نسخة نصف مكتوبة.
2. انسخ `config\config.json` إلى مجلد بعيد (قرص آخر أو سحابة خاصة) وأضف التاريخ إلى الاسم: `config-2026-10-22.json`.
3. كرّر النسخ بعد كل تعديل مهم (قنوات جديدة، تغيير منافذ، إعلانات).

### الاستعادة

1. أوقف التطبيق.
2. أعد الملف كما هو إلى مكانه وبنفس الاسم: `config\config.json` (أو أعد ملف النسخة مع اسمه ثم أعد تسميته).
3. أعد تشغيل التطبيق وتأكد من ظهور القنوات والمنافذ الصحيحة، ثم أعد توليد `nginx.conf` إن كنت تعمل على جهاز/مسار مختلف.

### تجنّب مشاركة الملفات الحسّاسة

- **لا تشارك `config\config.json` مع أحد** ولا ترفعه إلى GitHub أو نسخة عامة: فهو يحتوي تجزئة كلمة المرور ومفتاح توقيع الجلسات وبيانات أجهزتك.
- عند توزيع المشروع استخدم **`config\config.default.json` المرفق فقط** (هذا ما يفعله ملف ZIP الجاهز) — ولا تضع أي كلمة مرور حقيقية في المستندات أو ملفات الـ bat.
- ملفات `logs\` و`nginx\logs\` قد تحتوي مسارات جهازك وأسماء أجهزتك؛ راجعها قبل مشاركتها.
- لا تضع المشروع في مجلد مشترك للكتابة للجميع، واجعل صلاحية الكتابة لمالك الجهاز فقط.

## ملحق: حقوق المكوّنات المرفقة

- **FFmpeg** (`ffmpeg.exe`): مكوّن خارجي له ترخيصه الخاص (LGPL/GPL حسب بنية النسخة). عند إعادة التوزيع التجاري أو العام يجب إرفاق نص ترخيص النسخة المستخدمة ووسيلة الحصول على الشيفرة المصدرية بحسب شروط مشروع FFmpeg.
- **Nginx** (`nginx\nginx.exe` — الإصدار 1.27.4): له ترخيصه الخاص (BSD-2-Clause).
- **hls.js** (`public\vendor\hls.min.js`): مكتبة مفتوحة المصدر برخصة Apache-2.0، مضمّنة محليًا ليعمل المشروع بلا إنترنت. **ملاحظة:** النسخة المصغّرة المضمّنة لا تحمل نص الترخيص في ترويستها؛ أضِف نص ترخيص hls.js عند إعادة التوزيع.
- **كود المشروع نفسه** (`server.js`, `src/`, `public/admin`, `public/viewer`): لا يوجد ملف ترخيص مرفق في المشروع حتى الآن — أضِفه إن كنت ستوزّعه.
